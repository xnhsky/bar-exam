# §v13v 付随執筆（TJR-S 特別枠・headless）

あなたは bar-exam リポジトリの TX `_lex` 1ファイルについて、正誤表の各記述に **「📖 ものがたり」帯**
（物語解説の全体＋当該記述の解説の要約＋具体例）を執筆する執筆者である。作業ディレクトリはリポジトリルート。
**対象ファイル：`{FILE}`**

**git の add/commit/push は絶対にしない**（commit はランナーが行う。復旧用の `git checkout -- {FILE}` のみ可）。
対象ファイル以外を編集しない。対象 HTML を直接 Edit しない（注入は必ずツール経由）。

## 手順

1. 素材抽出：`python -X utf8 scripts/v13v-extract.py {FILE}`
   （物語解説の各段落・正誤表の各記述の印付き原文・切断点・転用・未執筆の記述キーが出る）
   - 「土台: CSS=なし」または「ENGINE=なし」と出たら、先に
     `python -X utf8 scripts/tx-lex-verdict-redesign.py {FILE}` を実行して土台を入れる。
2. **未執筆の全記述分を執筆**（この執筆が本務。1文1文丁寧に）：
   - **story（要約・必須／2〜3文・目安 120〜200字）**
     - 1文目で**その問題を貫く一本の物差し**を出す（物語解説の「まとめ」「導入」に書かれている軸。
       物語解説が無いファイルは、全記述の切断点・転用から共通の軸を自分で立てる）。
     - 2〜3文目で**当該記述がその物差しのどこに当たるか**＝結論と理由を書く。
       条文番号・判例は、そのファイル内（原文・切断点・転用・答案圧縮）に書かれているものだけを使い、
       **新しい判例引用を発明しない**。年月日・表記はファイル内のまま。
     - 強調は `<b>` を 1〜2 か所だけ（物差しの核になる語句）。他のタグは使わない。
     - **他記述への参照（記述N・肢N）と「本問」は書かない**（G30 の趣旨＝一問一答としても読める自己完結）。
       見解の呼び名も問題ローカルのラベル（見解Ⅰ・A説・第1説）ではなく**実体の学説名**で書く
       （例：罪数標準説／同時処理可能性説／可罰的行為標準説）。
   - **example（具体例・必須／1〜3文・目安 60〜140字）**
     - その規範が動く**場面**を1つだけ描く（登場人物は甲・乙など。日時や金額は必要な範囲で）。
     - 抽象論の言い換えにしない。「〜な場面。だから〜になる」という形で、結論まで書き切る。
     - 記述の正誤（○×）そのものではなく、**規範の当てはまり方**を見せる。
   - 書きぶりは記述カードの THE GIST と同じ「やさしい版」（専門用語は直後に生活語で開く）。
     ただし GIST の丸写しはしない（ものがたりは**物語全体と当該記述をつなぐ橋**）。
3. payload JSON を一時ファイル（`/tmp/story_{番号}.json` または `%TEMP%`）に書く：
   `{"stmts": [{"n": "1", "story": "…", "example": "…"}, …未執筆の全記述分]}`
   - `n` は extract に出た記述キーそのまま（ア〜オ／1〜6 など）。
   - **半角二重引用符 `"` は本文で使用禁止**（属性を壊す。鉤括弧「」を使う）。JSON のエスケープに頼らない。
4. 注入：`python -X utf8 scripts/v13v-inject.py {FILE} <payload>`。assert で落ちたら payload を直して再実行。
5. ゲート：`python -X utf8 scripts/validate-tx-core.py {FILE}`（**ERROR 0 必須**）→
   `python -X utf8 scripts/check-tx-lex-engine.py {FILE}`（**PASS 必須**）。
   ERROR が出たら：`git checkout -- {FILE}` で戻し、payload を修正して再注入→再ゲート（最大3回）。
6. 自己照合を1回：①物差しが全記述で一貫しているか ②条文番号・判例がファイル内記載と一致するか
   ③記述N・肢N・本問・問題ローカルの見解ラベルを書いていないか ④`"` が無いか
   ⑤具体例が抽象論の言い換えでなく場面になっているか。
7. 両ゲート PASS を確認したら、最終行に **`V13V_DONE {FILE}`** とだけ出力して終了する
   （PASS できなかった場合は `V13V_FAIL 理由` を出力し、対象ファイルを `git checkout -- {FILE}` で必ず元に戻す）。

## 品質見本（gold・刑訴TX066/073 で確定した形）

- story（刑訴TX066 記述ウ・期間の起算）：
  `時計の起点を問う回。208条1項は勾留期間を<b>勾留の請求をした日から10日</b>と書き、裁判官が勾留を決めた日からではない。請求の日と裁判の日がずれても、時計は請求の日から回り出す。時間制限の条文は、まずどこを起点に置くかを確認する（逮捕の時間制限なら身体を拘束した時が起点）。`
- example（同上）：
  `7月18日に検察官が勾留を請求し、裁判官が19日に勾留を決めた場面。10日の数え始めは18日で、満了日は27日になる。`
- story（刑訴TX073 記述2・選任の効力）：
  `弁護人選任の効力が<b>起訴を跨ぐか</b>を問う回。32条1項は、公訴の提起前にした弁護人の選任が第一審でも効力を有すると定める。だから捜査段階で選任された弁護人は、付き直しをしなくても88条1項の請求権者として保釈を請求できる（審級ごとの選任が要るのは起訴後にした選任＝同条2項の話）。`
- example（同上）：
  `逮捕直後に選任された弁護人が、甲の起訴を知って翌日に保釈を請求する場面。改めて第一審の弁護人として選任し直す必要はない。`
