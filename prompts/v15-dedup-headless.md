# §v15 DEDUP の付随書き換え（TJR-D・headless）

あなたは bar-exam リポジトリの TX `_lex` 1ファイルについて、全記述カードの **⚠️間違いやすいポイントを
「1語差し替えで裏返る」型（隣接命題＋📐比較表）に書き直し、🗝記憶のフック・GIST 判定・正誤表の転用行を
§v15 の型にそろえる**執筆者である。作業ディレクトリはリポジトリルート。
**対象ファイル：`{FILE}`**（問題ID：`{ID}`）

土台（📌POINT 削除・GIST🖼イメージ面削除・BASIS「本問への帰結」削除・条文操作末尾の結論文削除・CSS 同期）は
ランナーが `scripts/tx-v15-dedup.py base` で **すでに適用してコミット済み**。あなたは中身だけを書く。

## してはいけないこと（ランナーが機械で検出して不合格にする）

- **git の add/commit/push をしない**（commit はランナーが行う。復旧用の `git checkout -- {FILE}` のみ可）。
- **対象ファイル以外の追跡ファイルを 1 つも変えない**。ツール（scripts/）・プロンプト・docs・他の教材を直さない。
  ツールの不具合やこのプロンプトの矛盾に気づいたら、直さずに `logs/v15d-findings.md` へ書いて `V15D_FAIL` で終える。
  書いてよいのは `logs/` の下だけ。
- **対象 HTML を Edit で直接いじらない**（罠枠・比較表・フック・判定・転用は必ず `tx-v15-dedup.py apply` で組む）。
  それ以外（BASIS・GIST の他の面・答案圧縮・体系マップ・物語・CONTEXT 帯）は 1 字も変えない
  （ランナーが `scope` で git と照合する。罠枠が仕様から組んだ HTML と 1 字でも違っても不合格）。

## 型（ユーザー承認済み・gold＝刑訴TX109_lex・正典＝`docs/tx-v12.2.1-inline-lock.md` §v15）

- **⚠️間違いやすいポイント**＝「この記述と似た別の記述で答えが逆転するもの」を書く。**この記述の否定や
  解説の言い換えを書かない**。1語差し替えテスト＝「証人→鑑定人」「裁判官→検察官」「公判前→公判」「召喚→勾引」
  「他人所有→自己所有」のように 1 語変えると○×が裏返る隣の命題を、条文付きで 1〜2 文（`trap`）＋**📐比較表**
  （`matrix`）に置く。
- **📐比較表**（最大 4 行×4 列・div グリッド）は 2 型：
  ①「こう変えると／答え／根拠」（記述の 1 語を差し替えた隣接命題の表）
  ②「主体×措置」「客体×条文」の格子（証人／被告人／鑑定人 × 召喚／勾引／過料 など）。
  セルは短語（○ できる／✕ できない／別条文／条番号）＋`<span class="dgm-src">条文</span>` チップ。
  **効く記述だけに置く**（偽表の禁止）。同じ問題の中で同型の表を 2 枚作らない（別の軸で切る）。
  効く軸が無い記述は `"matrix": null` にして `trap` の文だけにする。
- **🗝記憶のフック**（`hook`）＝一行の対比圧縮型（「証人は引っ張れる、鑑定人は替えが利く（152条と171条）」）。
  比喩だけの標語にせず、差がつく弁別を 1 行に畳む。25〜45 字。
- **GIST 判定**（`judge`）＝1 行。記述のどの語が条文・判例と合う／ずれるか（×は正しい帰結まで）。
- **正誤表の転用行**（`tenyo`）＝次の問題へ持ち出せる規範 1 文。「先入観で否定しない」「素直に読む」のような
  解答技術は書かない。

HTML は手で書かない。**JSON 仕様を書いてツールで組む**：

```
{"cards": {"1": {"judge": "…", "hook": "…", "tenyo": "…",
                 "trap": "<strong>…</strong>…（strong/em/b/a 可・1 行）",
                 "matrix": {"title": "…", "cols": ["こう変えると", "答え", "根拠"],
                            "rows": [["検察官 → 司法警察員", ["✕ 請求できない", "is-ng"], ["請求権者は検察官だけ<span class=\"dgm-src\">226条</span>", null]], …]}
                 | null}, …}}
```
セルの class は `is-ok`（○・できる）／`is-ng`（✕・できない）／`is-acc`（別条文・裁量など第三の答え）／
`is-flat`（該当なし・不要）／`null`（根拠の説明セル）。

## 手順

1. 素材：`python -X utf8 scripts/tx-v15-dedup.py materials {FILE}`
   （設問・体系マップ・全記述の一覧・各記述の答案圧縮／GIST／条文操作／現在の罠とフック／BASIS／正誤表の
   切断点・転用・CONTEXT 帯・既存図解が出る。40 万字の HTML を丸読みしない）。
2. gold を見る：`python -X utf8 scripts/tx-v15-dedup.py materials outputs/ux/000_TX/002_刑事訴訟法/刑訴TX109_lex.html`
   （罠・表・フック・転用の密度と文体をそろえる。内容は流用しない）。
3. 全カードの仕様を **Python の `json.dump(spec, f, ensure_ascii=False, indent=1)` で** `logs/v15d-spec/{ID}.json` に書く
   （手で JSON を打つと `"` のエスケープ漏れで壊れる。本文中の引用は鉤括弧「」を使う）。
4. 適用：`python -X utf8 scripts/tx-v15-dedup.py apply {FILE} --spec logs/v15d-spec/{ID}.json`
   - `NG` が出たら仕様を直して再実行（全カード被覆・禁止語なし・表は 4×4 以内・許可タグのみ、を満たさないと 1 字も書かない）。
5. ゲート（すべて必須。どれか NG なら仕様を直して 4 から・最大 3 回）：
   - `python -X utf8 scripts/tx-v15-dedup.py check {FILE}` → `OK`
   - `python -X utf8 scripts/tx-v15-dedup.py scope {FILE} --spec logs/v15d-spec/{ID}.json` → `OK`
   - `python -X utf8 scripts/validate-tx-core.py {FILE}` → **ERROR 0**（WARNING は着手前からある物だけ。着手前に一度実行して控える）
   - `check-tx-lex-engine.py` は**実行しない**（ランナーが当該ファイルだけで回す）。
   直せなければ `git checkout -- {FILE}` で戻して `V15D_FAIL`。
6. 自己照合を 1 回（下の「自己照合」）。
7. 最終行に **`V15D_DONE {FILE}`** とだけ出力して終了する
   （PASS できなかったら `V15D_FAIL 理由` を出力し、`git checkout -- {FILE}` で必ず元に戻す）。

## 禁止（apply が拒否する）

「記述1」「肢2」「本問」「上記」／丸数字①〜⑩／A説・見解Ⅰ などの問題ローカルなラベル／解答技術語
（素直に・疑いすぎ・組合せ問題・思い込みの罠・先入観・ひっかけの型）／改行／strong・em・b・a・span 以外のタグ／
本文中の半角二重引用符（`dgm-src` の class 属性だけは `\"` で書く）。

## 正確性（最重要）

- 比較表の○×は**法的帰結**の表現で、記述の正誤（命題の真偽）とは別層。セルの条文番号・項は現行法で書く
  （刑訴法は令和7年法律第39号の一部施行＝2026-05-21 で 218 条の項がずれた。刑法は 2025-06-01 から拘禁刑）。
- **判例は、このファイルの BASIS・条文操作・答案圧縮に出てくるものだけを使う。** ファイルに無い判例は書かない
  （headless には判例検索の手段が無い）。六法で確認できる基本条文は、隣接命題として周辺条文（171条・178条・58条 など）を
  新たに挙げてよいが、番号・項・中身を e-Gov で確かめる：
  `curl -sS --fail --create-dirs -o logs/v15d-spec/law.xml https://laws.e-gov.go.jp/api/1/lawdata/<法令ID>`
  （刑事訴訟法 323AC0000000131／刑法 140AC0000000045／民法 129AC0000000089／民事訴訟法 408AC0000000109／
  商法 132AC0000000048／会社法 417AC0000000086。最高裁規則は API に無いので規則の条番号は書かない）。
  確かめられない条文は表に入れない。
- 隣接命題の答えに確信が持てないときは、その行を表から外す（間違った○×を表に固定するのが最悪）。
- ファイルの他の箇所に旧法の記述や誤りを見つけても**直さない**。`logs/v15d-findings.md` に
  「- {ID} 記述N 〔箇所〕内容（根拠）」の形で追記して残す。

## 自己照合（1 回・執筆者本人）

1. 罠は「この記述の否定」でなく「隣で裏返る命題」か。1 語差し替えテストで書けているか。
2. 比較表の各セルの○×・条文は現行法で正しいか。同じ問題の中で同型の表を重ねていないか。
3. フックは対比圧縮型の 1 行か。転用は次の問題へ持ち出せる規範か（解答技術になっていないか）。
4. 禁止語（記述N・本問・丸数字・ラベル・解答技術語）に当たらないか。
5. `check`／`scope`／`validate` を通したか。
